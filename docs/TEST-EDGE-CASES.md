# 극단 입력 검사표 (카드 3)

측정 방법은 눈대중이 아니라 **실제 렌더러를 호출한 뒤 캔버스 픽셀을 읽는 것**이다.
브라우저에서 `renderCard()` 를 그대로 불러 그린 다음 다음 값을 측정했다.

- `줄 수` — 줄바꿈 로직이 실제로 나눈 줄의 개수
- `요청 크기 → 그린 크기` — 자동 축소가 적용된 뒤의 글자 크기
- `세로 넘침` — 문구 블록 높이 − 캔버스 높이 (0보다 크면 잘린다)
- `가장자리 잘림` — 캔버스 네 변에서 글자 색과 같은 픽셀의 개수 (0이어야 한다)
- `alpha` — 모서리와 중앙 픽셀의 투명도

검사용 이미지는 `scripts/make-test-images.mjs` 로 직접 만들었다.
인터넷에서 가져오지 않았으므로 사용 권한 문제가 없고, 메타데이터도 들어가지 않는다.

### 08번에 대한 메모

원래 이 항목에서 가로 넘침이 날 것으로 예상했으나 나지 않았다.
글자 크기 상한이 400px 이고 문구 최대 폭이 972px(캔버스 1080px의 90%)이라,
한글 한 글자(400px)가 최대 폭을 넘는 상황이 **구조적으로 생길 수 없다**.
`LIMITS.fontSize.max` 를 400 으로 잡은 것이 결과적으로 가로 넘침을 막고 있다.

## 2. 대표 결함 — 문구가 세로로 넘쳐 잘림

12개 기본 항목만으로는 결함이 드러나지 않아, 조건을 더 밀어붙인 검사를 추가했다.
여기서 결함이 나왔다.

### 발견

| 검사 자료 | 블록 높이 | 캔버스 높이 | 세로 넘침 | 가장자리 잉크 |
|---|---|---|---|---|
| 긴 문장 + 300px, 1:1 | 6,300px | 1,080px | **5,220px** | 위쪽 260px |
| 긴 문장 + 300px, 9:16 | 6,300px | 1,920px | **4,380px** | — |
| 아주 긴 글 + 140px, 1:1 | 6,265px | 1,080px | **5,185px** | 아래쪽 110px |
| 문구 위치를 맨 위(0%)로 | 200px | 1,080px | 0 | 위쪽 280px |
| 문구 위치를 맨 아래(100%)로 | 200px | 1,080px | 0 | 아래쪽 285px |
| 문구 위치를 맨 왼쪽(0%)으로 | 150px | — | — | 왼쪽 86px |

캔버스 가장자리에 글자 픽셀이 닿았다는 것은 문구가 화면 밖으로 잘려나갔다는 뜻이다.

### 원인

두 가지가 겹쳤다.

1. **줄바꿈이 가로 폭만 본다.** `wrapText()` 는 한 줄이 최대 폭을 넘지 않게만 나눈다.
   문구가 길거나 글자가 크면 줄 수가 늘어나 블록 전체가 캔버스보다 높아지는데,
   이를 확인하는 곳이 아무 데도 없었다.
2. **위치를 그대로 좌표로 썼다.** `textY * height` 를 블록의 세로 중앙으로 삼았기 때문에,
   위치를 0% 나 100% 로 두면 블록의 절반이 캔버스 밖으로 나갔다.

두 경우 모두 **사용자에게 아무런 표시 없이** 잘렸다. 이것이 가장 나쁜 부분이다.

### 수정

`src/render/renderCard.js`

1. `layoutText()` 를 추가해 요청한 글자 크기를 **최대 크기**로 보고, 문구 블록이
   캔버스 높이의 90% 안에 들어올 때까지 크기를 줄인다. 줄이는 비율을 넘침 정도에서
   계산하므로 보통 두세 번이면 수렴한다. 하한은 8px.
2. 그린 블록의 사각형을 계산해 캔버스 여백 안으로 **가둔다**. 정렬 기준(왼쪽/가운데/오른쪽)에
   따라 기준점과 블록 왼쪽 끝의 거리가 달라지므로 그 값을 반영했다.
3. `renderCard()` 가 `{lineCount, fontSize, shrunk}` 를 돌려주도록 바꿔,
   자동 축소가 일어나면 편집 화면에 알린다.

> 문구가 길어 화면에 다 들어오지 않아 300px 대신 **46px** 로 그렸습니다. 내려받는 파일도 같습니다.

축소를 조용히 하지 않고 화면에 밝히는 쪽을 택했다. 사용자가 지정한 값과 실제 값이
다른데 알려주지 않으면, 그것도 일종의 거짓말이기 때문이다.

### 수정 후 재검증 (같은 입력)

| 검사 자료 | 요청 → 그린 크기 | 세로 넘침 | 가장자리 잘림 |
|---|---|---|---|
| 긴 문장 + 300px, 1:1 | 300 → **46px** | 0 | 0 |
| 긴 문장 + 300px, 9:16 | 300 → **82px** | 0 | 0 |
| 아주 긴 글 + 140px, 1:1 | 140 → **21px** | 0 | 0 |
| 문구 위치를 맨 위(0%)로 | 200 → 200px | 0 | 0 |
| 문구 위치를 맨 아래(100%)로 | 200 → 200px | 0 | 0 |
| 문구 위치를 맨 왼쪽(0%)으로 | 150 → 150px | — | 0 |

수정 뒤 12개 기본 항목도 다시 돌렸고 모두 통과했다.

### 회귀 확인

렌더러를 고쳤으므로 카드 2의 요구사항이 깨지지 않았는지 다시 확인했다.
축소가 일어난 상태에서 미리보기 캔버스와 내려받은 PNG 를 디코드해 대조한 결과
**차이 나는 서브픽셀 0개**. 자동 축소는 미리보기와 파일에 똑같이 적용된다.
