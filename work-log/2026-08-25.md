## 1. History 경계 결함 — 테스트를 쓰다 발견

전날 로그에는 "History boundary 테스트 추가"만 적혀 있었는데,
테스트를 쓰려고 코드를 읽다가 **실제 결함**을 찾았다.

### 증상

모습(Persona)을 고른 뒤 **0.6초 안에** 문구를 옮기면,
되돌리기 한 번에 문구 이동과 모습 변경이 **함께** 사라진다.

### 원인

`usePreset`/`useEra`가 `lastChangeAtRef.current = 0`으로 묶음을 끊었다.
이건 **앞쪽만** 끊는다. 직후 effect가 `lastChangeAtRef.current = now`로
덮어쓰므로, 0.6초 안의 다음 편집은 모습 단계에 흡수된다.

### 해결

시각 하나 대신 묶음 상태를 들고 다닌다.

```js
{ lastChangeAt, isolated }
```

`isolateBurst`로 표시된 변경은 자기 뒤에 시각을 남기지 않는다(`lastChangeAt: 0`).
그래서 앞뒤 어느 편집과도 묶이지 않는다.

판단 로직은 `history.js`의 순수 함수 `advanceBurst`에 뒀다. React 없이 테스트된다.

### 브라우저 확인 (단위 테스트만으로는 배선을 증명하지 못한다)

| | 결과 |
|---|---|
| 모습 → 시대 → 문구, 185ms 안에 연속 실행 | 3단계로 기록 |
| 되돌리기 3회 | 문구 → 시대 → 모습 순으로 하나씩 복원 |
| **수정 전 코드로 되돌려 같은 절차 재현** | 되돌리기 1회에 문구 + 시대가 **함께** 사라짐 |

마지막 줄이 중요하다. 고친 코드가 통과하는 것만으로는 결함이 있었다는 증거가 안 된다.

## 2. `persona: null` / `era: null` 비대칭 해소

- `era: null` → 거부 (`raw.era !== undefined` 검사)
- `persona: null` → **통과** (`raw.persona ?? base.persona`가 null을 기본값으로 흡수)

`?? `는 "필드가 없음"과 "null이 적혀 있음"을 구분하지 못한다.
era와 같은 규칙으로 맞췄다 — **없으면 기본값, 값이 있으면 반드시 검사.**

legacy 이관(`professional`/`chaotic` → `normal`)은 그대로 유지.

## 3. 접근성 — 실제 결함이었다

전날 로그에는 "Persona 그룹에 `aria-label` 추가"라고 적혀 있었는데,
확인해 보니 `aria-label`은 **이미 있었다.** 없는 건 `role="group"`이었다.

```jsx
<div className="preset-grid" aria-label="온라인에서 보여줄 모습">
```

role 없는 `div`의 `aria-label`은 스크린리더가 읽지 않는다. 그동안 무의미했다.
Era 그룹(`.era-timeline`)에는 `role="group"`이 제대로 있었다.

## 10. CI 에 테스트 추가 (처리 완료)

배포 워크플로가 `npm ci` → `npm run build` 만 해서, 테스트 56개가 배포
경로에서 한 번도 실행되지 않았다. `npm test` 를 `build` **앞에** 넣었다.
실패하면 job 이 거기서 멈춰 `upload-pages-artifact` 까지 가지 않는다.

### 초록불이 거짓말을 할 수 있었다

스텝을 넣고 초록불을 확인했지만, 그것만으로는 **테스트가 실제로 돌았는지
알 수 없었다.** 로그는 admin 권한이 없어 못 읽는다.

그래서 직접 확인해 봤다 — 테스트 파일이 하나도 없는 프로젝트를 만들어
`node --test` 를 돌리니 **exit 0**. "전부 통과" 와 "아무것도 실행 안 함" 이
똑같이 초록불로 보인다. 파일이 옮겨지거나 이름 규칙이 바뀌면 조용히 그렇게
될 수 있다.

통과 개수를 읽어 0 이면 실패시키도록 가드를 넣었다.

```
passed=$(awk '/ pass [0-9]+$/ { p = $NF } END { print p + 0 }' ...)
[ "$passed" -lt 1 ] && exit 1
```

로컬에서 양쪽 다 확인: 이 저장소 `통과한 테스트: 56` → exit 0,
테스트 없는 저장소 `통과한 테스트: 0` → exit 1.

**이제 초록불은 "테스트가 실제로 돌았고 전부 통과했다" 를 뜻한다.**
로그를 못 읽어도 그 사실이 보장된다 — 확인 방식이 구조로 바뀌었다.

## 11. 남은 테스트 공백 두 개 (처리 완료) — 66개

### 시대별 렌더 회귀

27개 조합(3 모습 × 3 시대 × 3 비율)의 그리기 기록을
`test/fixtures/era-render.json` 에 고정했다.

**해시가 아니라 기록을 통째로 저장했다.** 조합당 30개 남짓이라 파일이
감당할 만하고, 무엇보다 `git diff` 에 무엇이 달라졌는지 그대로 보인다.
해시만 저장하면 "달라졌다" 는 알아도 무엇이 달라졌는지는 알 수 없다.

실패하면 몇 번째 호출이 어떻게 달라졌는지 짚어 준다.

```
normal|2012|1:1 의 렌더가 달라졌다.
  처음 어긋난 호출: #53
    저장: fillText(COLOR 400,151.20,189.00) | fillStyle=#d8cdb4 ...
    현재: fillText(COLOR 400,151.20,188.89) | fillStyle=#d8cdb4 ...
```

**빈 테스트가 아닌지 확인함**: 좌표를 0.1px 옮기니 실패했다.
렌더가 결정적인지도 함께 검사한다(같은 입력 두 번 → 같은 기록).
`renderCard` 에 `Date`/난수가 없음을 확인했다 — 있었다면 필름 날짜 각인
때문에 스냅샷이 내일 깨졌을 것이다.

### 안전 영역

이 약속은 "안 그리게 조심한다" 가 아니라 **구조로** 지켜진다.
`showSafeArea` 는 `PreviewPanel` 의 지역 상태이고 `EditorState` 에 없다.
`renderCard` 는 `EditorState` 만 받으므로 가이드를 알 방법 자체가 없다.

그 구조가 무너지지 않는지 4가지로 고정했다 — 상태 필드, `renderCard` 소스,
템플릿/공유 링크, 9:16 렌더 기록의 하단 18% 사각형.

**빈 테스트가 아닌지 확인함**: 가이드를 캔버스에 그리도록 고치니
스냅샷과 안전 영역 테스트가 **둘 다** 실패했다.

배포본에서 PNG 바이트로도 증명했다.

| | |
|---|---|
| 가이드가 화면에 실제로 보였는가 | 예 (251×80 DOM 요소) |
| PNG 바이트 (끔 / 켬) | 151,985 / 151,985 |
| SHA-256 | 완전 동일 |

### 픽셀은 브라우저에서, 구조는 CI 에서

헤드리스 브라우저를 의존성으로 더하면 설치와 배포 CI 가 무거워진다. 그래서 나눴다.

- CI(node): 그리기 호출 기록 — 기기와 무관하게 결정적

브라우저 측정 결과 **18개 조합이 전부 다른 픽셀**이었다(겹침 0).
다만 **PNG 해시를 기준값으로 박지 않았다.** 바이트가 브라우저 폰트 렌더링과
PNG 인코더에 따라 달라져서 다른 기기에서 재현되지 않는다. 박아 두면 남의
기기에서 실패하는 테스트가 된다. 측정 기록으로만 남겼다
(`docs/SELF-CHECK.md` 11·12장).
