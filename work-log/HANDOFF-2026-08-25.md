## 2. 이번 작업에서 완성한 것

### 첫 화면과 경험 구조

- 첫 화면을 `같은 사진. 다른 시대. 다른 나.`라는 한 문장 중심의 포스터형 Hero로 개편했다.
- 2004·2012·2026을 드래그하거나 키보드로 탐색하는 `TemporalScanner`를 추가했다.
- 두 시대가 단순히 교체되는 대신, 움직이는 경계선 양쪽에서 동시에 보이도록 만들었다.
- Hero의 시대 선택은 편집 상태와 분리했다가 CTA를 누를 때만 Studio에 반영한다.
- 모바일에서는 시대 CTA를 누르면 설명문이 아니라 결과 미리보기로 바로 이동한다.

### 포트폴리오 서사

- Hero → 시대를 고른 이유 → 세 가지 정체성 → Studio 순서로 정보 구조를 다시 잡았다.
- `배너이미지/`의 두 이미지를 Hero Scanner와 Identity Archive에 사용했다.
- 작품 보기, 모바일 플로팅 미리보기, 30초 빠른 시작을 유지했다.

### 타이포그래피

- 한글 제목·본문: `Noto Sans KR`
- 영문 메타·연도·인덱스: `Archivo Narrow`
- 제목을 설명형 UI 문구가 아니라 전시 포스터처럼 보이도록 크기·행간·자간을 재설계했다.
- 모든 섹션을 동일한 editorial gutter와 번호 체계에 맞췄다.

## 5. 집에서 이어서 할 우선순위

1. 실제 휴대폰에서 터치 드래그 감도와 긴 페이지 스크롤을 확인한다.
2. `배너이미지/` PNG 두 장이 합계 약 3.8MB이므로 WebP/AVIF 변환을 검토한다.
3. 소개 섹션의 문장 길이를 최종 포트폴리오 문체에 맞게 한 번 더 압축한다.
4. README에 대표 스크린샷과 Live Demo 링크를 추가한다.
5. 마지막으로 Lighthouse에서 접근성·성능·모바일 점수를 기록한다.

추가 이미지가 꼭 필요한 단계는 아니다. 다음에 이미지를 더 구한다면 기능 화면을 늘리기보다
2004·2012·2026 각각의 질감이 분명한 동일 인물 사진 세트를 우선한다.

## 6. 주의할 점

- Canvas 렌더 결과와 페이지 UI의 색상은 별개다. UI 팔레트를 바꿀 때 렌더 스냅샷까지
  불필요하게 바꾸지 않는다.
- Hero Scanner 상태는 실제 EditorState와 분리돼 있다. CTA 이전에 편집 상태를 바꾸지 않는다.
- URL의 `#card=` 공유 상태를 Studio 이동 코드가 덮어쓰지 않게 한다.
- 사용자 이미지와 프롬프트 MD, `배너이미지/` 원본을 삭제하거나 이름을 바꾸지 않는다.
